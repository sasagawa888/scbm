## perm1/2：バックトラック時の変数ポインタ復元先を調査

`likes/2` は正常動作するが、`perm1([1,2,3],X)` は4解までは正常で、5解目が

```text
X = [3|v_4]
```

となる。

ログを比較すると、`rp=3` で変数ポインタの復元先が変化している。

最初の `rp=3`：

```text
varZs=30000001
varXs=30000002
varX =30000003
varYs=30000004
[v_1,v_4]
```

ところが `[2,3,1]` の後、`[3,...]` の枝へバックトラックした際の `rp=3`：

```text
varX =30000001
varYs=30000002
varY =30000003
varZs=30000004
[v_5,v_6,v_8]
```

同じ `30000001～30000004` が、

```text
最初                 復元後
30000001 = Zs        30000001 = X
30000002 = Xs        30000002 = Ys
30000003 = X         30000003 = Y
30000004 = Ys        30000004 = Zs
```

のように、異なるローカル変数へ割り当てられている。

したがって、単純な「allfail では一世代前を復元する」という問題ではない可能性が高い。

### 次回の調査点

`[2,3,1]` の後に発生する問題の `backtrack rp=3` が、

**どの back ラベルへ飛び、どの unpack コードを実行し、どの変数セットへ保存済みポインタを復元しているか**

を追跡する。

疑い：バックトラックで別の節／本体位置へ移動した際、保存時とは異なる変数配置に対してポインタを unpack している。

`[3|v_4]` の `v_4` が未束縛で残るのは、この変数対応関係のずれによる可能性が高い。

最初:
rp=3 np=1
Zs Xs X Ys

途中のcreate:
rp=3 np=2
X Ys Y Zs

問題のbacktrack:
rp=3 np=2
X Ys Y Zs
