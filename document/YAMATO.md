# SCBM-Prolog YAMATO方式 設計メモ

**2026年10月24日**

## 1. 基本構造

- 証明全体を一本の双方向リストで管理する。
- 各要素は証明オブジェクト（`obj`）とする。
- `pc`（Proof Counter）が現在実行するオブジェクトを指す。
- 各オブジェクトに実行先ラベルを記録する。
- GCCのcomputed gotoを使用し、`switch` は使わない。
- Cの再帰呼び出しを使わず、スタックオーバーフローを回避する。

## 2. メインループ

- 基本構造は `loop: ... goto loop;` とする。
- `pc` が指すオブジェクトを取得する。
- オブジェクトに保存されたラベルへ直接ジャンプする。
- 実行後、`pc` を更新してメインループに戻る。
- `success:` と `allfail:` は通常の実行処理から分離する。

```c
loop:
    obj = get_object(pc);
    goto *obj->label;
```

## 3. 証明オブジェクト

各オブジェクトに以下の情報を保存する。

- 実行先ラベル
- `arglist`（引数リスト）
- 変数ポインタ
- `front`、`back`（双方向リストの接続情報）
- 必要に応じて非決定的述語の選択状態

## 4. 本体部の生成

- 従来ラベルで処理していた本体部をオブジェクトとして生成する。
- `back` をたどって次の継続を見つける。
- 本体部のオブジェクトを順次 `cons` で接続する。
- 本体部の生成が完了したら `concat` で前半の証明リストと接続する。
- `concat` は前半が `NIL` の場合も許容する。
- 従来の本体部生成コードをできるだけ流用する。

## 5. 組込み述語

- `atom` から組込みC関数の呼び出し先を取得する。
- 呼び出し先の関数ポインタをオブジェクトに記録する。
- 実行時には共通の `builtin_call:` ラベルへジャンプする。
- そこから記録されたC関数を呼び出す。
- 既存の組込み述語コードを流用する。

## 6. 成功処理

- 証明リストの終端に `success` オブジェクトを配置する。
- このオブジェクトは `success:` ラベルへジャンプする。
- 成功時には解を報告する。
- 必要に応じて強制バックトラックを行う。
- 全ての選択肢が尽きた場合は `allfail:` で終了する。

## 7. バックトラック

- `backtrack()` をC関数として実装する。
- 双方向リストを逆方向にたどり、直前の選択可能な `nondet` を探す。
- `pc` をそのオブジェクトへ戻す。
- ローカルスタックを適切な位置まで巻き戻して解放する。
- 保存された変数ポインタと `arglist` を利用して実行環境を復元する。
- `goto loop` により再実行する。
- 双方向リストの古い部分は残しておき、`front` からたどれるようにする。

## 8. 変数管理

- 各オブジェクトが固有の変数ポインタを保存する。
- `arglist` もオブジェクトごとに保存する。
- 成功継続を通じて変数ポインタを親へ伝播させる必要がない。
- 各呼び出しの変数ポインタの一意性を保つ。
- バックトラック時にはローカルスタックと変数束縛を適切に復元する。

## 9. 既存コードの流用

以下の機能は既存コードをできるだけ流用する。

- `unify`
- 変数管理
- 述語検索
- 本体部生成
- 組込み述語
- その他のN-Prolog／SCBM-Prologの機能

主な変更対象は、従来のスタックに依存した成功継続・失敗継続の制御部分となる。

## 10. 開発方針

- 正式名称は引き続き **SCBM-Prolog** とする。
- YAMATOは新しい実行方式の開発計画名とする。
- KISS原則に従い、できるだけ単純な構造にする。
- 最初は `foo(X) :- write(X).` の動作を目標とする。
- 次に `likes/2`、再帰、バックトラックを順次検証する。
- 開発期間は1年を想定し、急がず着実に進める。

---

## 設計の核心

従来のSCBMでは、継続をスタック上で管理していた。

YAMATOでは、継続を証明オブジェクトとして双方向リスト上に配置し、`pc` によって実行を制御する。

これにより、Cの再帰呼び出しに依存せず、成功・失敗・バックトラックを統一的に扱う。

最大の狙いは、従来のSCBMで難航した再帰とバックトラックの干渉を、複雑な制御処理の追加ではなく、**データ構造の変更によって解消すること**にある。


# SCBM-Prolog YAMATO 設計メモ

## 証明列における失敗と節単位の復元

作成日：2026年10月24日

## 1. 基本方針

YAMATOでは、証明構造を**一本の双方向リスト「証明列（Proof Sequence）」**として表現する。証明列は単なる証明木の保存形式ではなく、述語の展開、実行、バックトラック、復元を行う実行構造である。

- 述語オブジェクトを節の本体部オブジェクト列に置換する。
- 失敗時には証明列を節単位で元の述語オブジェクトに復元する。
- 復元後、未試行の節があれば新しい本体部を生成して挿入する。
- 再帰と非再帰に同じ規則を適用する。
- Cの再帰関数や別の復元スタックに依存せず、証明列とオブジェクトの情報を利用することを目指す。

## 2. オブジェクトが保持する情報

- 元の述語オブジェクトは、置換前に接続していた左右のオブジェクトの情報を保持する。
- 本体部を生成するとき、その**先頭述語オブジェクトにマーク**を付ける。
- 先頭述語オブジェクトには、**展開元の述語オブジェクトのアドレス**を保存する。
- 元の述語オブジェクトは、復元まで解放・再利用しない。
- 各述語の最後の節の次には、完全失敗を表す **`allfail`** を置く。

## 3. 失敗と再試行の基本動作

1. 失敗が発生したら、証明列を逆方向にたどり、直前の非決定性述語を探す。
2. 再試行可能な節があれば、その節の展開をいったん復元する。
3. 元の述語オブジェクトを基点に次の節を選び、本体部を新しく生成する。
4. 新しい本体部を証明列に挿入して実行を続ける。
5. 最後の節まで試し終え、次が `allfail` なら完全失敗として復元動作に入る。

**基本サイクル：**

```text
節を選択 → 本体部を生成・挿入 → 実行
                                   │
                                   └→ 失敗
                                         ↓
                                  元の述語へ復元
                                         ↓
                                  次の節 / allfail
```

## 4. マークによる節単位の復元

本体部先頭のマークは、展開元への復元を示す。

1. マークされた先頭述語で失敗し、対応する選択肢を使い尽くした場合、その述語から**節終端まで**の展開部分を元の述語オブジェクトに置換する。
2. 元の述語オブジェクトに保存されている接続情報を利用する。
3. 復元された述語オブジェクトにもマークがあれば、同じ復元操作を繰り返す。
4. マークがなければ、その連鎖的な復元は完了。次の節の選択・本体部の生成・挿入へ移る。ただし次が `allfail` なら、さらに外側への失敗処理となる。

```text
本体部先頭で失敗 / allfail
              ↓
     元の述語objへ復元
              ↓
       マークがあるか？
          /       \
        ある       ない
         ↓          ↓
    復元を反復    次の節を試す
                    またはallfail
```

マークのある先頭述語自身に未試行の選択肢が残っている間は、それを先に試す。単に先頭に到達しただけで本体部全体を破棄するわけではない。

## 5. 双方向リストの再接続

元の述語オブジェクトには置換前の左右の接続先が残っている。

- **左方向**：保存済みの接続先を使って直接再接続できる。
- **右方向**：元の述語オブジェクトに保存された右側の接続先を終点として走査し、展開部分を切り離して再接続する。
- したがって復元の走査コストは、基本的には対象となる展開範囲の長さに依存する。

バックトラックで次の選択肢を探す位置と、証明列を元に戻す位置は**別の概念**として扱う。

## 6. `release` に組み込む

既存の `release` に、証明列の復元操作を組み込む方針。

- ローカルスタックの巻き戻しと、必要な変数束縛の解除を行う。
- 節の失敗時には元の述語オブジェクトへ戻し、次の節で改めて置換する。
- 完全失敗時にも元の述語オブジェクトへ戻す。
- `allfail` は、全節を使い尽くしたことを示し、復元動作に入る契機となる。
- 復元後にさらにマークがあれば、同じ処理を反復する。

## 7. 再帰と強制バックトラック

再帰呼び出しも通常の述語呼び出しと同じ置換・復元規則で扱う。

`select1/3` のように、強制バックトラックによって証明列への挿入が発生し、探索が続く場合がある。その場合は、証明列全体を不用意に初期状態へ戻さない。

一方、再帰先が全節を使い尽くして `allfail` に到達した場合は、該当する本体部を復元し、必要なら外側へ復元を連鎖させる。

```prolog
select1(X, [X|Xs], Xs).
select1(X, [Y|Ys], [Y|Zs]) :-
    select1(X, Ys, Zs).

perm1([], []).
perm1(Xs, [X|Ys]) :-
    select1(X, Xs, Zs),
    perm1(Zs, Ys).
```

`perm1/2` の本体部先頭は `select1/3` であり、その `select1/3` 自身も再帰的に展開される。各段階のマークと元のオブジェクトへのアドレスを利用して、内側から順に復元する構想である。

## 8. 設計の狙いと計算コスト

- 複雑な失敗継続の伝播を、証明列上の局所的な復元操作に置き換える。
- 復元を反復処理として実装し、Cの再帰呼び出しを避ける。
- 左側の再接続は定数時間、右側は展開範囲の走査を要する。
- 復元の累積コストはバックトラック頻度に左右されるため、性能は実測で評価する。
- PAIP方式との性能差は未検証。再帰関数の呼び出しだけでなく、環境保存・束縛解除・メモリ管理も比較対象となる。

## 9. 実装前に検証する点

1. **マークの保持**：先頭述語がさらに置換されても、復元先情報を失わないか。
2. **`allfail` の到達順序**：内側の選択肢を使い尽くしてから、正しい外側の復元へ移れるか。
3. **節終端の特定**：入れ子の展開や挿入があっても、右方向の走査が正しい終点で止まるか。
4. **束縛の整合性**：証明列、変数ポインタ、ローカルスタックが同じ論理状態へ戻るか。
5. **複数解**：`select1/3` と `perm1/2` で解を重複・欠落なく列挙できるか。
6. **完全失敗**：偶数判定のような再帰述語で、解がない場合に正しく失敗を伝播できるか。

## 10. まとめ

**失敗した節は元の述語オブジェクトへ復元し、次の節を改めて証明列に挿入する。全節を使い尽くしたら `allfail` から復元を開始し、マークがある限り外側へ復元を繰り返す。**

この一つの規則で通常の失敗、完全失敗、直接再帰、相互再帰を扱うことを目指す。

YAMATOの独自の実行構造は、一本の双方向リストである**証明列**。実装の第一目標は正しさであり、`select1/3`、`perm1/2`、偶数判定などで検証してから性能を測定する。

*本メモは設計案であり、アルゴリズムの完全性・正当性は今後の実装とテストで検証する。*
